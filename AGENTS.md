# AGENTS.md

Working agreement for any coding agent in this repository. Vendor-neutral; `CLAUDE.md` only imports
this file.

## What this is

A demo service that edits Word (`.docx`, `.doc`) and PDF documents with an LLM while preserving
layout. Read in this order: `docs/intent.md` (what and acceptance criteria AC-n), `docs/spec.md`
(architecture, contracts, glossary, decision records), `docs/plan.md` (steps, facts, deviations).

## Commands

All tasks go through `poethepoet`; CI runs the same commands.

```
uv sync                         # install (Python 3.12)
uv run poe lint                 # ruff check + format check
uv run poe test                 # unit tests, no LibreOffice, no live model
uv run poe test-all             # includes tests marked soffice (needs LibreOffice)
uv run pytest tests/test_docx_writer.py::test_name   # single test
uv run pytest -m live -k ollama # live model smoke tests
uv run poe eval                 # deterministic invariant suite over evals/fixtures
uv run poe eval-models --provider ollama --model qwen3.5:9b
uv run poe fixtures             # regenerate evals/fixtures
uv run poe serve                # FastAPI on :8000, UI at /ui
docker compose up --build       # app + LibreOffice; Ollama/LM Studio run on the host (APP_PORT)
uv run python scripts/cli_bridge.py  # host bridge so Docker can use the claude/codex/agy CLIs
```

## Rules that are specific to this codebase

- **The model never sees or returns a whole document.** Only `Segment` ID and text go out, only
  `Edit` ID and new text come back (`spec.md` 4.1). Do not add a code path that regenerates a
  document from model output.
- **Writers change text inside existing objects only.** DOCX: no edits to `w:pPr`, `sectPr`, the
  styles part, or anything outside the edited `w:p`. PDF: never move a block; new text goes on
  the original baselines inside `PdfSegment.avail` (the block widened horizontally into free
  space only, see `plan.md` Deviations).
- **The invariant checks in `src/ai_doc_editor/invariants.py` are the oracle.** Every check has a
  negative-control test. Do not weaken a tolerance or skip a check to make a test pass. If a check is wrong, say so and record it in `plan.md`.
- Tests that need LibreOffice are marked `soffice`; tests that need a running model are marked
  `live`. `uv run poe test` must stay green without either.
- Fixtures are generated by `evals/make_fixtures.py` and committed. Do not hand-edit them.
- Use the canonical terms from the glossary in `spec.md` section 1 (segment, edit, change, writer,
  provider, layout gate). One concept, one name across code, API and UI.
- Document text is untrusted input to the model. CLI providers run with tools disabled or read-only
  in an empty temp directory. The CLI bridge binds to `127.0.0.1` only and accepts no free-form
  command.
- Do not commit `ai-factory-kit/`, `CONTEXT.md`, `GRILL.md`, `samples/private/`, `runs/` or `.env`.
- Never push to a remote without the owner's explicit command.
- Documentation lives in `docs/obsidian/` (plain Markdown, an Obsidian vault). Before
  adding code, check `code-map/` for an existing function; after changing a source file, update
  its code-map note, the section note and `Timeline.md`.
- If implementation contradicts a fact in `plan.md`, log it under **Deviations** before continuing.
